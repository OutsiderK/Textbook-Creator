# Style Guide

教材的语言、视觉与学习理论规则。所有 stage 写正文/补充时都要遵守。

## 第一原则

**写出来的文本要让读者感觉是一本"已经打磨完成的书"。** 内部追溯/审计/状态机的痕迹不可见。

## 禁词清单（reader-facing 文本中）

以下词或模式**不允许**出现在 `book/` 任何 .md 文件正文中：

- `defer`、`future-unknown`、`TODO`、`待补充`、`待定`、`待完善`
- `新增`、`补充`、`v1.0`、`本次更新`、`本次新增`、`⚡新增`
- `(将在第 X 章中讲解)` 这类括号注释（除非章号已确定且引用必要）
- 时间戳：`2026-XX-XX`、`YYYY-MM-DD`
- 工作流元语言："本章 defer 文件系统细节"

承认无法深入要用**自然散文**：

- ✅ "这里先把『等待』理解为进程暂时不能继续推进；至于多个进程如何安全地等待和唤醒，我们会在并发控制中把它讲完整。"
- ✅ "完整的算法分析需要 X 概念支撑，我们先用一个直观的例子建立感觉。"
- ❌ "本章 defer X 到 ch07"
- ❌ "TODO：补充 Y 的细节"
- ❌ "(2026-04-15 新增)"

## 章节叙事顺序

每个核心机制按 **痛点 → 机制 → 例子 → 代价/边界** 展开：

1. **痛点**：什么具体场景让这个机制有意义？反直觉问题或失败故事。
2. **机制**：怎么工作？关键不变量是什么？最小自洽描述。
3. **例子**：能跑通的一个最小例子（哪怕是手算）。
4. **代价/边界**：在什么时候这个机制不适用、退化、需要变种？

避免"定义 → 性质 → 应用"的干燥结构。

## 章节结构（必备小节）

按顺序：

1. 学习目标
2. 上章回顾（散文化，三条以内）
3. 开篇问题（反直觉、具体）
4. 本章地图（含边界说明）
5. 正文（3-6 个小节）
6. 思维停顿（1-2 次，就近答）
7. 例题讲解
8. 常见误区
9. 本章小结
10. 关键术语
11. 练习与解答
12. 覆盖记录

## 学习理论参数

### 间隔重复（spaced repetition）

- 每章首"上章回顾" ≤ 3 条核心概念。
- 关键概念在后续章节自然散文中复现（不是显式"回顾"标题）。

### 测试效应（testing effect）

- 每章 `练习与解答` 2-5 题，每题必有答案/路径。
- 每章 1-2 处 `思维停顿`，提具体概念问题。
- KP 入 ledger 时填 `retrieval_hooks.local` 1-3 条；Stage C 写章时补 `retrieval_hooks.bridging`。

### 认知负荷（cognitive load）

- 单章核心 KP（`core: true`）目标 5-9 个。Stage B 决定是否突破。
- 主线（章节小节）数量目标 3-6 个，每个小节聚焦一个核心机制。
- detail_cards 不全部塞主线 —— `figure/example/exam_tip` 走例题或侧栏。

### 先行组织者（advance organizer）

- "本章地图" 段告诉读者本章要解决什么 + 哪些问题先建立入口、不在本章深入。
- 整书的 `course-skeleton.md` 是低承诺全景，读者随时可查"目前学到哪了"。

### 建构主义（constructivism）

- 每章先建可视化模型（痛点 + 直观图示），再形式化定义。
- 不要把读者当空白盘子。激活前置知识（"上章回顾"）。

## Markdown / 视觉规则

### 强调级别（节制使用）

- `**bold**` — 关键术语首次出现、小节内的结论性判断。
- `==高亮==` — 考试常考的 must-remember 区分。
- `<u>underline</u>` — 关键边界、不变量、因果链。
- `> **思维停顿**：...` — 概念停顿提问。
- `> **工程师视角**：...` — 真实系统设计取舍（可选，不强制）。

每章每段强调累计 **2-5 处**，不要过度。

### 图表（SVG）

触发条件（必考虑画图）：
- 文本首次定义图形约定（节点/边/箭头/字段意义）。
- 读者需追踪 3+ 个交互对象/资源/状态/页框/进程。
- 概念依赖方向性（请求/分配/引用/映射/控制流）。
- 机制随时间演变（调度/等待/唤醒/替换/分配）。
- 例题有关键中间状态决定下一步。

要求：
- 命名 `assets/figures/chXX-<concept>.svg`，slug 稳定。
- Markdown 引用：`![alt](../assets/figures/chXX-foo.svg)`（路径相对章节文件）。
- 单色可读，标签直接在 SVG 里。
- 必须 XML-parse 通过，转义 `<` 和 `&`。

不强求每章固定数量。**典型范围 2-5 张**，多由内容决定。

## 术语统一

- 同一术语在不同章节用同一中文。
- 首次出现时给英文：`**中文（English）** 解释。`
- 全局术语表在 `spec/terminology.md`，写章时遇分歧以那里为准。

## 散文密度

- 不允许整段 bullet list 替代散文（bullet 用作清单/枚举，不用作主线叙述）。
- 例题分步用 bullet/numbered 可接受。
- 章节小节首段必须是散文（**至少一句完整的解释或动机**），然后才能转 bullet。

## 一致性

- 章节模板里有的小节按顺序出现。
- 一致使用 `## 小节名`，不混用 `##` 和 `###` 作为主小节。
- 章节内部小节编号用 `### XX.1`、`### XX.2` 形式，与章号一致。

## Don't

- 不写"按惯例"、"显然"、"如众所周知" —— 它们对初学者是侮辱。
- 不写没有就近答案的提问。
- 不在正文出现工作流术语。
- 不在 supplement 写日期或版本。
- 不复制 PPT 原话作为正文 —— 用自己的话重写，但 detail_cards 的具体信息要保留。
