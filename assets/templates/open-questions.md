## OQ 条目格式

每条 open question 用以下结构：

```markdown
## OQ-NNN
- 问题: <一句话描述具体的问题>
- 入口章: chXX-slug
- 状态: open | closed
- 期望章节: <预期回答它的章节，可以模糊：例如"并发控制部分"。可省>
- 关闭于: chXX-slug      # 仅 status=closed 时必填
- 关闭 KP: <KP-id>       # 仅 status=closed 时必填
- 备注: <可选；为什么提出 / 关闭时的注解>
```

例：

```markdown
## OQ-001
- 问题: 进程间如何安全地等待和唤醒？
- 入口章: ch03-processes
- 状态: open
- 期望章节: 并发控制部分（ch06-ch07）
- 备注: ch03 在"进程退出"部分提到 wait 但没展开。
```

## 规则

- 提出 OQ 的章节必须在正文里**自然地**承认这个问题（用散文，不写 OQ-001）。
- 关闭 OQ 时，Stage C/D 必须能指出**具体哪个 KP** 回答了它。
- OQ 一旦关闭，不再重开 —— 如有进一步细化需求，新建 OQ-NNN+1。
- OQ id 用 `OQ-` 加三位数字，按顺序分配，不重用已删除号。
